# 2026.320.1402 — feat(debian)!: retire the non-CachyOS coder bed and its image

## Summary

Retires `check-debian-coder-pod` and the `debian-coder` image it was the only deploy definition of,
together with that image's skill and its routing node.

`debian-coder` was a kitchen-sink developer-workstation demo — neither charly's own machinery nor a
package build — so it is one of the nine `pod:`/`vm:` definitions the org's non-CachyOS retirement
deletes (opencharly/opencharly#1068). Per the operator's decision, a dropped definition takes its
now-bedless workload image with it, and its prose goes in the same cutover (R5).

Two commits: the retirement (`59e1cad`), then `3e756f2` completing the R5 sweep after the first
review round found the retired identifier still named in eight further places.

**What stays.** `check-debian-debootstrap-vm` — charly's own proof that the toolchain installs on a
from-scratch `debootstrap` Debian root — with its `debian-debootstrap` fixture, plus the
`charly-debian` package-build leg.

**`debian-builder` is not orphaned.** The `debian` base is what consumes it, exactly as with
`ubuntu-builder`, so its skill entries were reworded rather than deleted.

### The cross-repo claim, measured against its actual referrer set

The first round correctly rejected a "cross-repo" claim whose greps were scoped to one tree. A
namespace-qualified reference (`debian.<box>`) can only exist in a repo that **imports** the `debian`
namespace, so the referrer set is closed and checkable:

```
$ grep -rln "^\s*-\s*debian: '@github.com/opencharly/distro-debian" --include=charly.yml . | grep -vE '\.build|\.worktrees'
./charly/charly.yml
./plugin-herdr/charly/charly.yml     # a nested checkout of the SAME charly repo
./pod-herdr/charly/charly.yml        # ditto

$ grep -nE '\bdebian\.(debian-coder|check-debian-coder-pod)\b' charly/charly.yml
rc=1   # no match

$ grep -rnE '\bdebian\.debian-coder\b' --include=*.yml . | grep -vE '\.build|\.worktrees'
(no matches — whole materialised clone)
```

So the only project in the org that can name `debian.*` is `opencharly/charly`, and it names neither
the retired box nor its bed. The claim is bounded by a measurement of the referrer set, not by one
directory.
