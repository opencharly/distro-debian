# 2026.320.2214 — fix(debian): put the vm deploy substrate in the bed's candy closure

## Summary

Adds the **vm deploy substrate** to `check-debian-debootstrap-vm`'s `add_candy:` closure. The bed could not
deploy at all before this:

```
[vm-create] PASS · [wait-ready] PASS · [deploy-add] FAIL after 3.536s
  error: command "deploy": the "vm" deploy substrate is not available in this project —
    its deploy plugin (plugin-deploy-vm) is not in the candy closure.
    Compose it, or add_candy: something that pulls it in
```

Head `25f2f14`, **1 file, 7 insertions(+)** — one `add_candy:` entry plus the comment recording why.

A bed that drives `charly check run` against a VM target needs the deploy **substrate** in its own candy
closure, not just the VM source. This bed declared `layer-charly` and nothing else, so the substrate was
absent and the deploy failed before a single guest check ran.

**Why this survived until now:** every VM bed in the org was stopped two steps *earlier* by the decoder
defect (opencharly/spec#341), so nobody reached `deploy-add` to see it. With the decoder fixed, the bed gets
far enough to fail here — which is how it was found.
